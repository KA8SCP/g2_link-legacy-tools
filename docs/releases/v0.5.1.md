# Unified D-STAR Dashboard v0.5.1

October 27, 2026. Stable maintenance release following v0.5.0.

## Changes

- Initial installation now requires recognized fixed PHP packages for CVE-2026-109618 and CVE-2026-109619 (PHP2Shell). It checks the packaged CLI, common engine and installed mod_php/FPM runtimes, rejects mismatched or unknown builds, and checks for workers retaining replaced PHP code. A failed prerequisite stops before dashboard download/deployment and is recorded in the private transcript.
- Package identity/footer, runtime checksum manifest, installer default tag and installation/update documentation now identify v0.5.1.
- Add PHP 5.4-compatible security-policy tests and isolated Linux wrapper/initial-install stop tests. Existing dashboard, updater, transcript and theme checks remain required.

No dashboard behavior changes beyond the package version. The updater preserves site configuration/ownership and continues to select the latest stable release by default. The security gate applies to first installations; an existing-dashboard update is not PHP security certification. No PHP packages, repositories, services, certificates, web routes or gateway settings are changed automatically.

## First installation

Run as root on an existing configured gateway, using a new checkout directory:

```bash
install_dir=$(mktemp -d /root/g2-dashboard-v051.XXXXXXXX) &&
git clone --branch v0.5.1 --depth 1 \
  https://github.com/KA8SCP/g2_link-legacy-tools.git "$install_dir" &&
bash "$install_dir/scripts/install-dashboard-interactive.sh" --package-dir "$install_dir"
```

Have an installed g2_link executable, nonempty status feed, DPlus inputs and working web PHP integration ready. An unverified PHP build must be patched or separately qualified before installation; there is no override. See ../PHP-SECURITY.md for accepted builds, sources and limits.

## Existing dashboards

The four gateways' PHP packages were patched and web services restarted separately by the administrator. Updating to v0.5.1 is optional for their display; it supplies the new numbered installer tools and footer identity.

```bash
update_dir=$(mktemp -d /root/g2-dashboard-v051.XXXXXXXX) &&
git clone --branch v0.5.1 --depth 1 \
  https://github.com/KA8SCP/g2_link-legacy-tools.git "$update_dir" &&
bash "$update_dir/scripts/update-dashboard.sh" --ref v0.5.1
```

Use an unpinned current updater to select the latest stable release. No gateway-service restart is required by the dashboard update.

## Qualification and limits

All four sites installed v0.5.0 with local HTTP verification; WB1GOF/W4CRL display acceptance was reported, with K2BWK display shown. Subsequent PHP remediation was verified on all four through installed package output, relevant service restart and local HTTP 200. Public HTTP/HTTPS access was confirmed on WB1GOF and VE3TTT after removing their temporary restrictions. These are operator results, not v0.5.1 live-install claims.

The new security gate is tested with isolated fixtures, not exploit traffic or production gateway changes. It trusts installed RPM metadata and recognizes a bounded vendor/version policy; it is not a compromise scan or a guarantee about custom binaries, containers or remote FastCGI backends. Administrators must confirm the web route uses the checked runtime. PHP/OS maintenance and the external certificate-renewal configuration issue remain separate. Prior attribution and history are retained; v0.5.0 is not retagged.

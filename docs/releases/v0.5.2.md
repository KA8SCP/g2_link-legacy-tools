# Unified D-STAR Dashboard v0.5.2

Published October 31, 2026. Stable dashboard/tools release for existing configured DPlus/g2_link gateways. It does not install or replace Icom, DPlus, MonLink, g2_link or PHP.

## Fixes

- Display XRF/DExtra remote activity logged as `START from remote g2`, preserving suffixes and headers with uniquely confirmed historical link/source/IP evidence.
- Preserve reflector history when a separate inbound dashboard/client identity such as `1NFO` expires. Genuine link timeout, restart, ambiguity and missing evidence remain conservative.
- Add a fresh-site check of the actual selected web route after approval and before dashboard/site-config deployment. A temporary token-only index.php verifies PHP execution, basic capabilities, temporary storage and CLI/web version agreement. Raw source, wrong pages and HTTP failures stop deployment with guidance; probes are cleaned up.
- Preserve existing index.php files, legacy dashboards and unrelated assets. Existing destinations still require final deployed HTTP verification/rollback.
- Document `QSO_DETAILS=Y`, append logging, native systemd versus shell launchers, Apache/mod_php and Nginx/PHP-FPM readiness, and site-specific routes.

## New installation (VE3RXR or another gateway)

First confirm g2_link/DPlus already operate, the real executable/status/log paths, a configured PHP web route and the actual worker identity. Enable `QSO_DETAILS=Y` for detailed incoming activity, preserve logs and verify append mode before activating any gateway configuration change. Keep existing 1NFO authentication settings.

```bash
git clone --depth 1 --branch v0.5.2 https://github.com/KA8SCP/g2_link-legacy-tools.git
cd g2_link-legacy-tools
sudo bash scripts/install-dashboard-interactive.sh --package-dir "$PWD"
```

For VE3RXR, enter callsign `VE3RXR` and its actual log timezone; do not assume another site's settings. Review document root/destination, log paths, worker ownership and local verification URL. If PHP was installed or patched, validate and restart the applicable Apache/mod_php or PHP-FPM runtime before proceeding; no automatic service restart is performed.

The default new unified dashboard is a separate /dashboard/ directory. The installer does not replace legacy status pages, change reflector links or rewrite Icom proxy routes. The fresh-site probe is temporary and secret-free. A permission/routing failure must be corrected through the site's administration procedure, not bypassed.

## Existing dashboard update

From a current tools checkout:

```bash
sudo bash scripts/update-dashboard.sh --ref v0.5.2
```

Use `--check-url` with the site's working local route where needed. Omitting --ref selects the latest published stable release. Saved configuration/ownership, private transcripts, backups and HTTP rollback remain supported. A dashboard-only update does not require a routine service restart.

## Qualification and limits

125 local dashboard checks passed for the candidate activity code; Linux CI also covers PHP syntax, runtime hashes, security policy, themes, transcript handling, updater preservation/rollback and the new readiness probe's failure/cleanup cases. The stable promotion changes identity/source selection, not the activity logic already accepted by operators.

Operator reports: WL7CWI XRF on rc.1; WB1GOF DCS recovery, K2BWK/VE3TTT display/activity and VE7VIC XRF on rc.2. VE7VIC required a scoped Nginx route and activation of QSO_DETAILS; its native service already appended both output streams.

**The new readiness probe has isolated test coverage, but its live fresh-install acceptance remains pending. VE3RXR is planned, not yet qualified.** Existing-target probing is deliberately skipped to avoid replacing live entry points. Final HTTP rendering, real transmissions and public HTTPS/Icom continuity must be checked separately.

This is not a PHP vulnerability scan or universal certification of CentOS/AlmaLinux builds. The PHP2Shell package prerequisite remains separate; unknown vendor packages require review. Missing/stale/unsupported historical evidence remains Unknown and does not prove RF delivery.
